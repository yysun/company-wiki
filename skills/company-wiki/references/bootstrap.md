# Bootstrap a Personal Wiki

Require an explicitly selected visible Company Library Index (registered profile or exact native home target) and a
separate writable Personal Wiki destination. Verify identity, personal-destination write capability, and audience.
Check [Publication](publication.md) for the index reference's current disclosure authorization and any explicitly
required continuous inheritance; a generic label does not make an index link exempt. If required authorization is
unavailable, create nothing and offer the authorized transient reference. Missing future-inheritance proof alone
does not block ordinary provider-managed Bootstrap; do not invent a different Bootstrap route.
A legacy profile cannot authorize Bootstrap. If the selected index is unavailable, create nothing and offer
direct-source Query only when the user supplies an accessible exact source location.

Missing protected-create or registration support likewise leaves only an authorized transient reference proposal
under [capability levels](publication.md#capability-levels); no personal home or registry entry is created.

Do not sample the company corpus, read index child pages, copy the index, bulk-generate pages, chunk/embed
documents, or require a database. Treat the supplied index-home target as opaque: create a minimal personal home
with a `Company Library Index` link only—no child title, alias, summary, or relationship. Include readable sections
for pinned nodes, temporary nodes, personally canonical nodes, and `Do not automatically Curate` topics.

Record a direct-source locator verbatim only when separately supplied by the user; never adopt a boundary declared
by the index. Without it, explicitly mark broad direct-source search unavailable. Apply through the
[durable change protocol](change-protocol.md), then register required profiles.
